# oneread

A private library of things you'd rather listen to. Paste in an article, a
chapter, tomorrow's talk. Give it a title and some tags, pick a voice, and it
comes back as a wav file with subtitles timed to the audio.

Speech is generated by [Supertonic 3](https://github.com/supertone-inc/supertonic),
which runs as ONNX inside this app. No API keys, no requests leaving the
machine, no per-character billing. The model weighs about 385 MB and is baked
into the Docker image at build time.

## What it does

Each entry holds a title, the text, optional tags, and the voice settings used
to read it. Text comes in as plain (the default, read exactly as typed) or as
markdown. Markdown gets flattened before it reaches the voice: headings lose
their hashes and become their own line, list items are read one per line, links read their label instead of the URL, images read their alt text,
task lists say "done" or "to do", and code fences are announced ("Code block in
python, 12 lines") rather than dictated character by character. Tables are the
awkward case, so they're read as sentences: the columns are named once, then
each row comes back as "Row 2. Name: Grace. Role: Admiral." Symbols a voice
can't pronounce become words, so `≥` reads as "greater than or equal to". One search box covers all three of title, text and tags, backed by
SQLite's FTS5 index, so it stays quick as the library grows.

Text can also arrive as a file. Drop one on the editor and the words come back
into the box before anything is saved, so you can read them over and fix what
came out wrong. It takes a Word document, a deck, a spreadsheet, a CSV, a PDF
you can select text in, markdown, plain text, the OpenDocument three, rich text
or a saved web page. A `.md` file arrives as markdown; everything else is
plain text. Spreadsheets are the interesting case: read cell by cell they're
noise, so each sheet is named, the columns are read once, and every row comes
back as "Row 1. Region: North. Units: 412." Slides are numbered and their
speaker notes come along.

The file itself is kept, because extracting is one-way and the original is the
only way to check what got left behind. On the entry's page it's named right
beside the text it produced, with its kind and its size, and pressing it hands
you the file back exactly as it went in. Beside that is the text the voice
reads, as a plain `.txt`. Editing the text never touches the file.
Two formats need help: `.doc` and `.ppt`, which have no reliable Python reader
and are passed through LibreOffice if `ONEREAD_SOFFICE_PATH` points at one.
Without it you get a note suggesting you save the file as `.docx` first. A PDF
that turns out to be photographs of pages says so rather than producing an
entry with nothing in it. There's no OCR here.

Entries can be long. The ceiling is 100,000 characters, which is a short book:
roughly two hours of audio and around half an hour of CPU. Nobody should have to
spend that to find out the voice was wrong, so a new entry gets read for one
minute and stops there. You listen, and then you decide. Three and five minutes
are on the same switch if a minute isn't enough to judge by.

"Make a recording" opens the panel where the rest of it happens. Three ways to
ask: a taster of one, three or five minutes; a section, picked with a two-handled
slider; or the whole document. The slider counts sentences rather than seconds,
so a range can only ever begin and end on a whole one, and it shows you the
sentence at each handle along with where that falls on the timeline. Voice,
language and speed sit in the same panel, so trying a different reader is a
change of dropdown rather than a trip through the editor, and "Hear it" is right
there to check before committing. Whatever you pick becomes the entry's default
for next time.

Every option shows what it will cost first: how long the audio will be, how long
the machine will take, how many lines it is. Those numbers are measured, not
guessed. Every finished reading records its characters, its audio and its wall
clock, so the next estimate is calibrated to this voice on this hardware. The
first estimate on a fresh install says so.

While a full reading runs the entry is frozen, because changing the text
underneath a half-finished recording produces something that matches neither
version. Stop is always available, and stopping keeps the audio. A reading
interrupted at 37% is a real file with real subtitles; it downloads as
`title-partial.wav` so it can't be mistaken for the whole book later. A restart
does the same thing rather than throwing an hour of work away.

So an entry collects readings rather than having one recording. The one-minute
sample, the full run, chapter four on its own, the partial from the time you
stopped early, an older take in a different voice: each has its own player, its
own subtitles, and its own delete button. The one the library leads with is
whichever covers the most of the document, newest among equals.

The library is a grid of small tiles: title, two lines of text, and a play
button for whichever reading is the most complete. That's all a card does.
Opening one goes to `/e/<id>`, where each recording is its own small card
labelled in plain words: "the first minute", "the whole thing", "stopped part
way", with a green tick when it covers everything and a badge on whichever one
the library plays. Each carries a bar showing which slice of the document it is,
the sentence it opens on, and when it was made, because two recordings both
called "the first minute" are otherwise impossible to tell apart. Times are
stored and served as UTC and shown in whatever timezone you're sitting in;
hover a "4 minutes ago" for the exact local moment. That one has no Remove button, and the server refuses to
delete it, so an entry with audio can't be left without any. Make a newer
recording and the old one is free to go. Next to each is a small card listing
its files by what they're for rather than by extension, with the audio's size
on it. The
text sits at the bottom behind a two-way switch, "what it reads" against your
original, which is the only way to check a markdown table or a code fence landed
the way you meant. Keeping the two
apart means a shelf of fifty entries stays a shelf rather than fifty control
panels.

Audio is written to disk a sentence at a time rather than assembled in memory,
so a two-hour entry costs no more RAM than a two-minute one. On this machine a
3,120-character entry produced 231 seconds of audio in 53 seconds, about four
times faster than real time, and grew the process by under 100 MB.

Accounts work the way a shared kiosk should: type a user id and a password. A
new id creates the account, the same pair signs you back in later. Everyone's
entries are theirs alone.

Signing in sticks. The session cookie lasts a month and renews itself whenever
you use the app, so someone who reads regularly is never asked again. The key
that signs those cookies is generated once into `data/secret.key` and reused, so
restarting the server doesn't quietly log everybody out. Set `ONEREAD_SECRET_KEY`
if you'd rather keep it out of the data directory or share one across machines.

"See what gets read" in the editor shows the same thing while you're still
writing, before a generation is spent on it.

Before generating anything you can press "Hear it" in the editor and listen to
the exact settings you picked. It reads the first sentence of your
own text, so you hear the settings on the actual material rather than a canned
line. Samples are cached, so flicking between voices is instant after the first
listen.

Subtitles are the part worth explaining. The app doesn't ask the model how long
each sentence will be; it synthesizes sentence by sentence and reads the cue
boundaries off the sample count of the audio it just wrote. The last cue ends on
the same millisecond the wav does. Download the `.srt` and the `.wav` together
and they line up in VLC, or hit "Follow along" in the player and watch the line
light up as it's spoken.

## Running it

### Docker

```sh
cp .env.example .env
docker compose up --build -d
```

The first build downloads the model, so give it a few minutes. After that the
image is self-contained. Open http://localhost:8000.

The database and the wav files live in `./data`, mounted into the container.
Back that directory up and you've backed up everything. Upgrading in place is
fine: missing columns get added to the existing SQLite file at startup, and any
recording made before entries could hold several becomes that entry's first
reading, so an older `data/` directory keeps working.

### Local development

Needs Python 3.12 and Node 22.

```sh
make install
make dev-backend     # API on :8000
make dev-frontend    # Vite on :5173, proxying /api
```

Vite serves the UI during development. `make serve` builds the frontend and
hands the whole thing to FastAPI on one port, which is how it runs in
production.

```sh
make test    # 105 tests, no model needed
make lint
```

The suite swaps in a fake engine that writes silent wav files, so it finishes in
about a second. To hear real audio you need the model, which downloads to
`~/.cache/supertonic3` on first use.

## Putting it on the internet

Terminate TLS in front of the app and set two things:

```sh
ONEREAD_COOKIE_SECURE=true
ONEREAD_ALLOWED_HOSTS=oneread.example.com
```

Without the first, session cookies travel in the clear. Without the second, the
app answers to any Host header. There's a commented Caddy service in
`docker-compose.yml` that handles certificates if you don't already have a
reverse proxy.

Once the people who need accounts have them, set
`ONEREAD_ALLOW_REGISTRATION=false`. New user ids stop working, existing ones
keep signing in.

A few things are already handled: argon2 for passwords, an HttpOnly signed
session cookie, a custom-header CSRF check on every write, token-bucket limits
on sign-in and on generation, and a content security policy that blocks remote
scripts. What isn't handled is horizontal scale. The model sits in one process's
memory and synthesis runs on a single thread behind it, so run one worker and
give it CPU rather than running several. Watch the disk too: an hour of audio is
about 300 MB, so a library of long entries adds up faster than the database does.

## Settings

Every setting is an environment variable prefixed `ONEREAD_`, or a line in
`.env`. The full list with defaults is in `.env.example`. The ones you're most
likely to touch:

| Variable | Default | What it does |
| --- | --- | --- |
| `ONEREAD_SECRET_KEY` | generated into `data/secret.key` | Signs session cookies. Set it to keep the key elsewhere. |
| `ONEREAD_DATA_DIR` | `./data` | Database and audio files. |
| `ONEREAD_MAX_TEXT_CHARS` | `100000` | Ceiling on one entry's text. |
| `ONEREAD_MAX_UPLOAD_BYTES` | `26214400` | Biggest file that will be read. |
| `ONEREAD_SOFFICE_PATH` | empty | Path to LibreOffice, which adds `.doc` and `.ppt`. |
| `ONEREAD_SAMPLE_MINUTES` | `1` | How much of a new entry gets read straight away. |
| `ONEREAD_GENERATE_PER_HOUR` | `30` | Per user. |
| `ONEREAD_PREVIEW_PER_HOUR` | `120` | Voice samples, per user. |
| `ONEREAD_TTS_STEPS` | `8` | More steps, slightly better audio, more CPU. |
| `ONEREAD_PRELOAD_MODEL` | `true` | Load ONNX at startup so the first entry isn't slow. |

## How it's put together

```
backend/oneread/
  main.py         app factory, lifespan, serves the built frontend
  config.py       settings
  db.py           SQLite engine, the FTS5 table and its sync triggers
  models.py       User, Entry, Rendition, Upload
  estimates.py    how long a reading will be, calibrated from finished ones
  auth.py         argon2, signed cookies, the CSRF check
  markdown_speech.py  markdown flattened into words a voice can say
  extract.py      uploaded files turned into speakable text, with the zip guards
  segmenter.py    text into sentence-sized pieces, one per cue
  tts_engine.py   Supertonic held open, per-segment synthesis, cue timings
  subtitles.py    cues into SRT and WebVTT
  worker.py       the job queue and its one thread
  routers/        auth, entries, renditions, meta, preview, uploads
frontend/src/
  screens/        AuthGate, Library, EntryPage
  components/     DownloadCard, EntryCard, EntryEditor, FileDrop, FileKind,
                  GeneratePanel, GlassPlayer, MiniPlayer, RangePicker, ReadingCard,
                  SpokenPreview, TagInput, TextPanels, VoicePreview
  styles/         tokens.css, glass.css, app.css
```

The interface leans on Apple's translucent materials: `backdrop-filter` over a
soft colour field, a bright top edge where light catches the surface, and
springs rather than fixed-duration slides. It respects
`prefers-reduced-motion`, `prefers-reduced-transparency` and
`prefers-contrast`, and follows the system light or dark setting.

### API

| Route | |
| --- | --- |
| `POST /api/auth/login` | Sign in, or create the account if the id is new |
| `POST /api/auth/logout` | |
| `GET /api/auth/me` | |
| `GET /api/entries?q=&tag=` | Search and filter. Returns summaries: an excerpt, not the text |
| `POST /api/entries` | Create and queue generation |
| `GET /api/entries/{id}` | The full entry: text, spoken version, every reading |
| `PUT,DELETE /api/entries/{id}` | Refused with 409 while a full reading runs |
| `GET /api/entries/{id}/source` | The file the text came out of, exactly as uploaded |
| `GET /api/entries/{id}/text.txt` | The words the voice reads, as a plain file |
| `GET /api/entries/{id}/segments` | Every sentence with its place on the timeline |
| `GET /api/entries/{id}/estimate?scope=` | Audio length and wall clock, before committing |
| `POST /api/entries/{id}/renditions` | Start a reading: `sample`, `range` or `full`, with voice, language and speed |
| `GET /api/renditions/{id}` | One reading, with its cues |
| `POST /api/renditions/{id}/stop` | Stop it and keep what's been read |
| `DELETE /api/renditions/{id}` | |
| `GET /api/renditions/{id}/audio?download=1` | Range requests supported |
| `GET /api/renditions/{id}/subtitles.srt` | |
| `GET /api/renditions/{id}/subtitles.vtt` | |
| `POST /api/uploads` | Read a file. Returns its words; saves nothing yet |
| `DELETE /api/uploads/{id}` | Throw away a file that never became an entry |
| `POST /api/preview` | A few seconds of the chosen voice, as wav |
| `POST /api/preview/text` | The flattened text, without synthesizing anything |
| `GET /api/meta` | Voices, languages, limits |
| `GET /healthz` | |

Writes require the header `X-Requested-With: oneread`. A cross-site form can't
set it.
